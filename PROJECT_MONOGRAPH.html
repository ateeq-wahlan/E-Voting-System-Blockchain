ABSTRACT

Executive Technical Summary

Traditional paper-ballot and centralized electronic voting systems face persistent challenges regarding security, credibility, transparency, recount overhead, and single-point-of-failure vulnerabilities. While pioneers such as Estonia demonstrated national-scale internet voting, centralized database architectures still require blind trust in the administering authority.

In this project, we design and implement a fully decentralized E-Voting System Using Blockchain Technology that manages the complete electoral lifecycle—from voter biometric enrollment and party ballot registration to encrypted vote casting, Proof-of-Work block mining, and real-time public auditing. Once voting commences, the platform operates independently without allowing any central administrator to alter or delete cast ballots. Voter identities are protected via HMAC-SHA256 Zero-Knowledge Nullifiers and Additive Homomorphic Commitments, ensuring complete ballot secrecy alongside public mathematical verifiability.

System Design, Class Hierarchy & Biometric Sequence Flow

Following the Umbrella SDLC Model (Requirements Gathering → Requirements Traceability Matrix → Object-Oriented Design → Coding → Integration & Acceptance Testing), the architecture is structured around five primary object classes (Fig. 8 Class Diagram):

  • Voter (v_id, v_password, v_name) → cast_vote(), view_result()
  • Cast (cand_id, voter_id, timeStamp) → submit_vote(), cancel_vote()
  • Candidate (cand_id, cand_name) → submit_nomination(), cancel_nomination()
  • Admin (voter_id, voter_name) → add_party_detail(), view_party_detail(), view_votes(), submit_report()
  • Result (cand_id) → votes_count(), display(cand_id)
CHAPTER 6 // IMPLEMENTATION & NORMALIZED DATABASE SCHEMA

3NF Relational Schema (`database.sql`) & Cryptographic Engine (`Block.py`, `Blockchain.py`)

To eliminate data redundancy and update anomalies, the relational layer is normalized through First Normal Form (1NF: `Voter` / `register`), Second Normal Form (2NF: `Election` & `addparty`), and Third Normal Form (3NF: `Ballot` & `Voting`), paired with the SHA-256 Proof-of-Work ledger (`difficulty = 2`).
